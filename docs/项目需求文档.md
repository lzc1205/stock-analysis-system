## 一、项目概述

### 1.1 项目背景

构建一个面向个股的金融数据仓库与可视化大屏系统，实现从多源金融数据采集、清洗、存储到可视化展示的全链路闭环。系统支持股票行情数据、财务指标、技术指标的自动化入库，并通过大屏直观呈现个股走势、资金流向、财务健康度等核心维度。

### 1.2 项目目标

| 目标维度 | 具体描述 |
|---------|---------|
| 数据采集 | 支持 A 股个股日线/分钟线行情、财务报表、资金流向等多源数据自动采集 |
| 数据仓库 | 按 ODS→DWD→DWS→ADS 四层建模，保证数据可追溯、可复用 |
| 可视化 | 提供大屏级别的数据展示，支持 K 线图、指标雷达图、资金流向图等 |
| 自动化 | 数据采集、清洗、计算全流程定时自动化，无需人工干预 |

### 1.3 适用范围

- 数据范围：A 股个股（可扩展至港股、美股）
- 用户范围：个人投资者、金融数据分析爱好者
- 部署范围：本地部署 / 私有服务器部署

## 二、系统总体架构

### 2.1 架构分层图

```
┌─────────────────────────────────────────────────────────────┐
│                    可视化展示层 (Presentation)                │
│   Vue3 + ECharts + DataV 大屏  │  AI 问答对话组件           │
├─────────────────────────────────────────────────────────────┤
│                    应用服务层 (Service)                       │
│   数据查询 API  │  AI 智能问答服务  │  技术指标计算  │  缓存  │
├─────────────────────────────────────────────────────────────┤
│                    数据仓库层 (Storage)                       │
│   MySQL 数据仓库  │  分层建模 ODS/DWD/DWS/ADS                │
├─────────────────────────────────────────────────────────────┤
│                    数据采集层 (Collection)                    │
│  Baostock / AkShare(主)  Tushare(可选)  │  APScheduler 定时  │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 数据流

```
数据源(Baostock/AkShare为主, Tushare可选) → 采集脚本 → ODS层(原始数据)
    → 数据清洗 → DWD层(明细数据)
    → 指标聚合 → DWS层(汇总数据)
    → 业务宽表 → ADS层(应用数据)
    → FastAPI → Vue3大屏展示
    → AI问答服务 → 自然语言查询 → 大模型生成解读回答
```

## 六、数据仓库设计

### 6.1 分层架构

| 层级 | 全称 | 作用 | 数据特点 |
|-----|------|------|---------|
| **ODS** | Operational Data Store | 贴源层，原始数据原样入库 | 与源系统一致，不做清洗 |
| **DWD** | Data Warehouse Detail | 明细层，清洗后的标准明细数据 | 去重、空值处理、格式统一 |
| **DWS** | Data Warehouse Summary | 汇总层，按主题聚合的宽表 | 按天/周/月聚合，预计算指标 |
| **ADS** | Application Data Store | 应用层，面向大屏的最终数据表 | 直接供前端查询，高度聚合 |

### 6.2 核心数据表设计

#### ODS 层（原始数据表）

| 表名 | 说明 | 主要字段 |
|-----|------|---------|
| ods_stock_daily | 日线行情原始数据 | ts_code, trade_date, open, high, low, close, vol, amount |
| ods_stock_basic | 股票基本信息 | ts_code, symbol, name, industry, market, list_date |
| ods_daily_basic | 每日基本面指标 | ts_code, trade_date, turnover_rate, pe, pb, total_mv, circ_mv |
| ods_moneyflow | 资金流向 | ts_code, trade_date, buy_sm_vol, sell_sm_vol, net_mf_vol |
| ods_income | 利润表 | ts_code, ann_date, end_date, revenue, n_income, eps |
| ods_balancesheet | 资产负债表 | ts_code, ann_date, end_date, total_assets, total_liab, total_hldr_eqy |
| ods_cashflow | 现金流量表 | ts_code, ann_date, end_date, n_cashflow_act, n_cashflow_inv |

#### DWD 层（清洗明细表）

| 表名 | 说明 | 处理逻辑 |
|-----|------|---------|
| dwd_stock_daily | 标准日线行情 | 去重、复权处理、空值填充、涨跌幅计算 |
| dwd_stock_info | 股票维度表 | 统一行业分类、ST标记处理 |
| dwd_financial_indicator | 财务指标明细 | 统一报告期、同比环比计算、异常值过滤 |

#### DWS 层（汇总宽表）

| 表名 | 说明 | 聚合维度 |
|-----|------|---------|
| dws_stock_daily_wide | 个股日度宽表 | 行情+基本面+资金流向+技术指标，按股票+日期 |
| dws_industry_daily | 行业日度汇总 | 按行业+日期聚合涨跌家数、平均涨幅、总成交额 |
| dws_stock_weekly | 个股周度汇总 | 按股票+周聚合，周K线数据 |

#### ADS 层（应用层表）

| 表名 | 说明 | 服务对象 |
|-----|------|---------|
| ads_stock_overview | 个股总览数据 | 大屏顶部概览卡片 |
| ads_kline_data | K线图数据 | 大屏K线图组件 |
| ads_technical_radar | 技术指标雷达图数据 | 大屏雷达图组件 |
| ads_capital_flow | 资金流向数据 | 大屏资金流向图 |
| ads_financial_health | 财务健康度评分 | 大屏财务分析模块 |

### 6.3 数据库初始化脚本（示例）

```sql
-- 创建数据库
CREATE DATABASE IF NOT EXISTS stock_warehouse
  DEFAULT CHARACTER SET utf8mb4
  DEFAULT COLLATE utf8mb4_unicode_ci;

USE stock_warehouse;

-- ODS层：日线行情表
CREATE TABLE IF NOT EXISTS ods_stock_daily (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  ts_code VARCHAR(20) NOT NULL COMMENT '股票代码',
  trade_date DATE NOT NULL COMMENT '交易日期',
  open DECIMAL(10,3) COMMENT '开盘价',
  high DECIMAL(10,3) COMMENT '最高价',
  low DECIMAL(10,3) COMMENT '最低价',
  close DECIMAL(10,3) COMMENT '收盘价',
  pre_close DECIMAL(10,3) COMMENT '昨收价',
  `change` DECIMAL(10,3) COMMENT '涨跌额',
  pct_chg DECIMAL(10,3) COMMENT '涨跌幅(%)',
  vol DECIMAL(20,2) COMMENT '成交量(手)',
  amount DECIMAL(20,2) COMMENT '成交额(千元)',
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_ts_date (ts_code, trade_date),
  KEY idx_trade_date (trade_date)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='ODS-日线行情原始数据';
```

### 7.3 AI 智能问答助手模块设计

#### 7.3.1 模块定位

AI 智能问答助手是系统的智能交互入口，用户可以用**自然语言**提问，系统自动理解意图、查询数据仓库、生成专业解读回答。无需用户编写 SQL 或理解数据结构，降低使用门槛。

#### 7.3.2 核心功能

| 功能 | 说明 | 示例提问 |
|-----|------|---------|
| **行情查询问答** | 自然语言查询个股价格、涨跌幅、成交量等 | "贵州茅台今天涨了多少？"、"最近一周宁德时代的成交量趋势如何？" |
| **Text-to-SQL** | 自动将自然语言转为 SQL 查询数据仓库 | "帮我查一下2024年涨幅最大的10只股票" |
| **技术指标解读** | 解释技术指标含义，给出多空判断 | "比亚迪的MACD现在是什么状态？有没有金叉？" |
| **财务分析问答** | 解读财务报表，分析盈利能力、偿债能力 | "招商银行的ROE连续三年是多少？变化趋势如何？" |
| **资金流向分析** | 分析主力资金、北向资金动向 | "今天贵州茅台主力资金是流入还是流出？" |
| **多轮对话** | 支持上下文追问，保持对话连贯性 | 用户："茅台今天怎么样？" → 助手回答 → 用户："那最近一周呢？" |
| **投资建议（谨慎）** | 基于数据给出参考性分析，明确提示非投资建议 | "从技术面看，这只股票现在适合买入吗？" |

#### 7.3.3 技术架构

```
用户提问
  ↓
[意图识别] → 判断是行情查询/财务分析/技术解读/闲聊
  ↓
[Text-to-SQL 生成] → LangChain + 大模型生成 SQL
  ↓
[SQL 安全校验] → 禁止 DROP/DELETE/UPDATE，仅允许 SELECT
  ↓
[执行查询] → 从 MySQL 数据仓库获取数据
  ↓
[结果组装] → 将查询结果 + 上下文组装成 Prompt
  ↓
[大模型生成回答] → 生成自然语言解读，附带数据支撑
  ↓
返回用户（前端对话组件展示）
```

#### 7.3.4 大模型选型

| 模型 | 费用 | 接入方式 | 推荐度 |
|-----|------|---------|-------|
| **豆包大模型（Doubao）** | 有免费额度，按量付费 | OpenAI 兼容接口 | ⭐⭐⭐⭐⭐ 国内访问快，中文好 |
| 通义千问（Qwen） | 有免费额度 | OpenAI 兼容接口 | ⭐⭐⭐⭐ 阿里出品，稳定 |
| 智谱 GLM | 有免费额度 | 原生 API | ⭐⭐⭐⭐ 中文理解强 |
| OpenAI GPT | 按量付费，需科学上网 | 原生 API | ⭐⭐⭐ 效果好但国内访问不便 |

> **推荐**：使用**豆包大模型**，国内访问稳定、中文金融领域理解好、有免费额度，且兼容 OpenAI SDK 格式，代码可无缝切换。

#### 7.3.5 核心 Prompt 设计（Text-to-SQL）

```
你是一个金融数据分析师，擅长将自然语言问题转换为 SQL 查询。

## 数据库表结构
{table_schema}

## 规则
1. 只生成 SELECT 查询，禁止任何修改操作（INSERT/UPDATE/DELETE/DROP）
2. 股票代码格式：600000.SH（沪市）/ 000001.SZ（深市）
3. 日期格式：YYYY-MM-DD
4. 涉及涨跌幅时，使用 pct_chg 字段
5. 查询结果限制最多 100 行
6. 如果问题模糊，给出最合理的查询并在回答中说明假设

## 用户问题
{user_question}

## 请输出：
1. 生成的 SQL 语句
2. 简短的查询说明（1-2句话）
```

#### 7.3.6 安全与合规约束

| 约束项 | 具体措施 |
|-------|---------|
| **SQL 注入防护** | 仅允许 SELECT 语句，关键字白名单校验，参数化查询 |
| **数据量限制** | 单次查询最多返回 100 行，防止大查询拖垮数据库 |
| **投资建议免责** | 所有分析类回答末尾自动附加："以上内容由AI生成，仅供参考，不构成投资建议" |
| **对话历史管理** | 单用户最多保留 20 轮对话上下文，Redis 缓存，超时自动清除 |
| **敏感词过滤** | 对输入输出进行敏感词检测，防止违规内容 |
| **限流控制** | 单用户每分钟最多 10 次提问，防止 API 滥用 |

#### 7.3.7 API 接口设计

```

响应：

  "intent": "行情查询",

}
```

## 十一、风险与注意事项

| 风险项 | 说明 | 应对措施 |
|-------|------|---------|
| 数据源接口限流 | AkShare 爬取公开网站可能被限流 | 加入重试机制 + 请求间隔控制，合理安排采集时间，Baostock 作为备用 |
| 数据源失效 | AkShare 依赖第三方网站，网站改版可能导致接口失效 | 关注 AkShare 官方更新，多数据源互为备份，Baostock 稳定性更高 |
| TA-Lib 安装困难 | Windows 下编译依赖复杂 | 提供预编译 whl 包，或使用纯 Python 的 `ta` 库替代 |
| 数据量增长 | 全市场股票多年数据可达千万行 | 按日期分区建表，建立合适索引，冷热数据分离 |
| 复权处理 | 前复权/后复权逻辑容易出错 | 使用 Baostock 官方复权参数，编写单元测试验证 |
| 大屏性能 | 大量数据渲染可能卡顿 | 后端预聚合到 ADS 层，前端按需加载，使用 WebWorker |
| **AI 幻觉问题** | 大模型可能生成不准确的金融数据或分析 | Text-to-SQL 模式下所有数据来自数据库，大模型只做解读；关键数据附带来源；设置低 temperature |
| **AI SQL 安全** | 大模型生成的 SQL 可能包含危险操作 | SQL 安全校验器，仅允许 SELECT，关键字白名单，禁止多语句，限制返回行数 |
| **AI API 成本** | 大模型调用产生费用 | 设置用户限流，缓存常见问题回答，使用有免费额度的模型，监控调用量 |
| **投资建议合规** | AI 给出的分析可能被用户当作投资建议 | 所有回答末尾自动附加免责声明，明确提示"仅供参考，不构成投资建议" |
